<Section index="01" kicker="The exercise" title="Why six agents">

The Agentic Lab is a separate, self-contained exercise: teams of five, one session, a synthetic e-commerce retailer whose cross-sell engine is ordinary collaborative filtering, backward-looking, segment-level, and blind to a customer's actual moment. It can't tell that a shopper buying baby products for three months has fundamentally different needs than a college student buying the same bedding. Team 6's assignment, Scenario B, is a Life-Stage Basket Optimizer built to fix that, and to do it without crossing from personalization into surveillance.

<PullQuote
  quote="If an agent cannot say no it is an automation. The kill-switch and escalation rule are design rules not safety features you bolt on at the end."
  attribution="Agentic Lab brief"
/>

Every agent in the design has to specify ten things: name, persona, skill, trigger, input fields, reasoning logic, output, autonomy level, escalation rule, kill-switch condition, plus an eleventh Team 6 added on its own: what it must *not* do. One monolithic agent can't hold six distinct kill-switch conditions and stay auditable; splitting the pipeline is what makes each boundary checkable on its own, independent of the others. Autonomy level for each agent runs the same [cost-of-error, value-of-speed calculation](/spine/economics-of-error) as everywhere else in this handbook, just labeled by level instead of by name.

<DefinitionList items={[
  { term: 'L1 — Inform', body: 'The agent surfaces information only. A person holds full decision authority.' },
  { term: 'L2 — Recommend', body: 'The agent proposes an action; a person approves it before anything ships.' },
  { term: 'L3 — Act with override', body: 'The agent acts on its own; a person monitors and can intervene mid-flight.' },
  { term: 'L4 — Autonomous', body: 'A person sets the rules up front and reviews outcomes after the fact, not before each action.' },
]} />

Two findings from profiling the data before any prompt was written drove the entire six-agent shape. One was about which rules actually predict a life stage; the other, sharper, was about what a system should never infer from a customer's purchase history. Both show up below.

</Section>

STRATA and APEX run in parallel on genuinely independent data, purchase history against session events, with no shared state between them. SENTINEL is a required gate. There is no path by which ARC receives a candidate pool without passing through it first. LENS runs alongside STRATA and APEX and feeds ARC directly with a review summary, not a candidate list. It never touches who gets recommended, only how the recommendation reads.

<PullQuote quote="When in doubt, withhold. A confident wrong summary is worse than no summary." attribution="LENS agent prompt" />

</Section>

<Section index="03" kicker="The adaptation" title="Basket optimization across life stages">

STRATA classifies into five life-stage codes, new_parent, college_bound, homeowner, pet_owner, gift_giver, plus a deliberate default, general, that fires below a 0.55 confidence threshold rather than force a guess.

<Stat id="agentic-lab-confidence-calibration" />

APEX works on a different axis entirely: a real-time strength score built from five primary and five secondary session signals, high engagement, cart intent, search-query intent, repeat consideration across sessions, and recent cart abandonment among the primaries. That score, not a life stage, is what decides how aggressively ARC is allowed to personalize in the moment.

A weak or absent classification doesn't make ARC guess anyway. It collapses the recommendation back to neutral collaborative filtering with no life-stage language at all. Restraint is the default state, not an exception the system reaches for occasionally.

</Section>

<Section index="04" kicker="The finding" title="The sensitive-signal trap">

Profiling the retailer's data before writing a single prompt surfaced the first warning sign: naive life-stage rules, taken straight from the brief, perform badly against the dataset's hidden ground-truth labels.

<Stat id="agentic-lab-naive-precision" />

That's what pushed STRATA's actual homeowner rule to trade recall for precision deliberately, rather than follow the brief's looser version. The second finding is sharper, and it's the single most important result in the whole exercise.

<Example id="agentic-lab-sensitive-trap">
The obvious proxy for "this is a sensitive customer" is "this customer bought a sensitive product," a crib, a baby monitor, nursery safety gear. Checked against the dataset's hidden flag, that proxy performs *worse than doing nothing*: customers who bought a sensitive product turn out slightly less likely to actually be in the protected category than customers who never did. The obvious signal points backward.
</Example>

The conclusion Team 6 wrote directly into SENTINEL's prompt: suppression has to live on the product side. Don't aggressively cross-sell crib safety gear, full stop, regardless of who's shopping. Never treat it as a behavioral inference about the customer. That became a hard prohibition with its own dedicated kill-switch, not a soft guideline a later prompt revision could quietly soften.

</Section>

<Section index="05" kicker="Defense in depth" title="The three-layer guardrail pattern">

Three separate checkpoints catch what the others miss, rather than one checkpoint trying to catch everything.

<DefinitionList items={[
  { term: 'Layer 1 — Consent, at the front', body: 'GATE hard-terminates on an opt-out before any reasoning agent fires. No downstream agent ever sees data about a customer who opted out. Not a warning after the fact, a stop before the start.' },
  { term: 'Layer 2 — Pool integrity, mid-pipeline', body: 'SENTINEL strips sensitive, quality-degraded, and fake-review-cluster SKUs from the candidate pool before ARC ever receives it. The ranking agent never has the option to rank something that should never have been a candidate.' },
  { term: 'Layer 3 — Surface check, at the end', body: 'ARC carries its own kill-switches as a last line of defense, covering a sensitive SKU reaching a non-new-parent, a slot populated without justification, and biography language on a customer STRATA never actually classified.' },
]} />

Eight branch-coverage test cases exercise every path through that pattern, the clean case, the sensitive-product-to-non-new-parent case, the anonymous shopper, the serial returner, the opt-out, the out-of-stock product, each with a named expected outcome, saved as evidence for the governance appendix rather than left as an informal spot-check.

</Section>
