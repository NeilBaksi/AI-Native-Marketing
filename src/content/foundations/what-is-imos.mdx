The last chapter named the gap without naming what fills it. This course calls that missing layer the **Intelligent Marketing Operating System** — I-MOS for short: the coordination layer that connects customer signals, marketing decisions, content creation, journey execution, and performance learning into one continuous, governed system.

That's a dense sentence, so it's worth taking apart. I-MOS isn't a product you buy — no vendor ships "an I-MOS." It's an architecture: a specific way of connecting the tools an organization already owns (or will own) so that what one workflow learns, the next one can actually use, automatically, without a person carrying it across by hand.

<Callout kind="key" title="Three things that make it an operating system, not a stack of tools">
This course names three defining characteristics. **One system, not many tools** — the workflows share memory instead of each holding its own disconnected copy of the truth. **Always-on, not campaign-by-campaign** — it runs continuously, the way a server runs, not the way a launch runs. **Trusted by design, not by exception** — governance is built into how the system executes, not added afterward as a review step.
</Callout>

<Section index="01" kicker="The work" title="Seven workflows, three phases">

I-MOS organizes marketing's actual work into seven workflows: Sense, Focus, Design, Attract, Orchestrate, Execute, and Learn. They group into three phases. **Understand** (Sense, Focus) is figuring out who the customer is and what they need. **Build** (Design, Attract) is making the assets and getting them discovered. **Run** (Orchestrate, Execute, Learn) is putting the right message in front of the right person and getting smarter from the result.

Two things about this diagram matter more than the seven names. First, the arrow from Learn back to Sense: results aren't the end of the chain, they're an input to the next cycle — the same distinction between an operating system that has memory and a campaign process that resets to blank each time. Second, Govern isn't a phase in the sequence — it's a band running underneath all seven, continuously, not a gate a campaign passes through once before launch. Later chapters in Part III each take one workflow and go deep; this diagram is the map they're all zooming into one node of.

<Section index="02" kicker="The machinery" title="What actually runs underneath">

The seven workflows describe the *work*. Underneath them, I-MOS is built from four layers, each with a rough body-system metaphor the course uses to make the abstraction concrete.

<DefinitionList items={[
  { term: 'Shared Memory', body: 'The hard drive and the brain — the persistent record of what the system knows about each customer and what happened last time, so nothing resets between cycles.' },
  { term: 'Agentic Services', body: 'The organs — the individual AI-driven capabilities that do the actual work of each workflow, reading from and writing to Shared Memory.' },
  { term: 'Orchestration', body: 'The nervous system and the conductor — the layer that sequences which service acts when, and routes each workflow\'s output to the next workflow that needs it.' },
  { term: 'Governance', body: 'The immune system — consent, claims, bias, and audit checks running inside execution, not as a separate review step bolted on after.' },
]} />

A later chapter in Part II goes through each layer in enough detail to be useful; this is the version worth carrying forward for now: work happens in the Agentic Services layer, gets remembered in Shared Memory, gets sequenced by Orchestration, and Governance runs through all three continuously rather than checking them afterward.

</Section>
