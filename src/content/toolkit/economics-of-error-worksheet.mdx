<Section index="01" kicker="Four questions, documented" title="What it's for">

[The Economics of Error](/spine/economics-of-error) defines the formula, cost of error weighed against value of speed, and four diagnostic questions that turn it into an autonomy tier. This page doesn't redefine any of that. It's the worksheet. A fixed set of prompts you run a real decision through. The tier it lands on is a documented answer to four questions, not a gut call made once and never revisited.

<Callout kind="note" title="Read the framework first">
This worksheet assumes you already know what the four tiers are and why cost-of-error and value-of-speed are the two variables. If either of those is new, start at [The Economics of Error](/spine/economics-of-error). This page only operationalizes it.
</Callout>

</Section>

<Section index="02" kicker="Before autonomy gets set" title="When to use it">

Run this worksheet before a decision gets handed to an AI agent for the first time, not after something has already gone wrong with it. It's also the right tool when two people disagree about how much autonomy a decision deserves. Instead, both sides answer the same four questions and see where the disagreement actually lives, rather than arguing preferences.

- Scoping a new agent or workflow, before any autonomy level gets set in configuration.
- Revisiting a decision that's drifted — a Fully Autonomous action that started causing damage, or a Human-in-Command decision that's become a bottleneck.
- Settling a dispute about whether something "should" be automated, by making the inputs explicit instead of arguing conclusions.

</Section>

<Section index="03" kicker="Pause vs. resume, split apart" title="Worked example">

A subtlety the worksheet is built to catch: what looks like one decision is often two, and the two halves can land on different tiers. Take "should the system be allowed to react to a paid social campaign's performance without a person approving it first?" Run the four questions separately for *pausing* underperforming spend and *resuming* it.

    { label: 'Value of acting faster', cells: ['High — every hour of continued bad spend is a real loss.', 'Low — there is no offsetting value in resuming quickly if the underlying cause was never found.'] },
    { label: "AI's confidence in this call", cells: ['High — "CPA crossed a threshold" is exactly the pattern-detection AI is good at.', 'Low — "why did CPA spike, and is it fixed" is a diagnostic judgment, not a pattern match.'] },
  ]}
/>

Answer the same four questions for each half and the tiers split apart: pausing clears Fully Autonomous, resuming lands at Human in the Loop or higher. Treating "campaign reaction" as one decision with one tier would have either left bad spend running for hours, or gated every pause behind a person. That's the wrong failure, in both directions.

</Section>

<Section index="06" kicker="A decision is rarely atomic" title="Design decision">

The one habit this worksheet is built to force: don't assume a decision is atomic. A single-looking action, "react to campaign performance," "respond to a support signal," "adjust a bid," routinely bundles a cheap, reversible half with an expensive, hard-to-reverse one. Scoring the bundle as a single tier always gets one half wrong. Running the four questions per sub-action lets the tiers land wherever they land, even asymmetrically, one high and one low, on what reads as a single workflow step. That keeps the worksheet honest, instead of just producing whatever tier the person filling it out already wanted.

</Section>
