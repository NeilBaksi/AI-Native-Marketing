The seven workflows name the work. This chapter names what the work runs on — and the course is explicit that this isn't optional detail: remove any one of the four layers below and the system breaks, no matter how well the workflows themselves are designed.

<Section index="01" kicker="Layer 1" title="Shared Memory: the hard drive">

Today, customer truth is fragmented across a CDP, a CRM, a data lake, an identity graph, and a consent platform — different vendors, brittle integrations, conflicting customer IDs for the same person. Shared Memory replaces all five with one logical layer that every agent reads and writes in real time, organized into five object types: identity, state, decision, content, and learning.

That fifth type is the one easy to miss. Learning objects are what Session 10 called the write-back — incrementality by channel, drift alerts, model performance by segment — the layer where Learn's output becomes next cycle's starting input instead of a slide nobody revisits.

<Section index="02" kicker="Layer 2" title="Agentic Services: the applications">

An agentic service isn't one AI tool bolted onto a workflow — it's a coordinated team of autonomous agents, each with a defined scope, communicating with each other through Shared Memory rather than through a person relaying context between them. The course's own comparison: an ER department, where a triage nurse, a specialist, a technician, and a pharmacist each have a clear role, and the shared patient record is what keeps all of them aligned without a meeting.

Six services cover the seven workflows between them (Focus and Orchestrate each get their own; Attract and Execute share Activation): Signal (Sense), Decisioning (Focus + Orchestrate), Content Assembly (Design), Journey Orchestration (Orchestrate), Activation (Attract + Execute), and Experimentation & Measurement (Learn) — the only service whose output flows backward to update the others, rather than forward to the next one.

</Section>

<Section index="03" kicker="Layer 3" title="Orchestration: the conductor">

Session 10 states this layer's absence bluntly: most martech stacks today are an orchestra of brilliant instruments with no conductor. Every individual tool can be excellent and the system can still fail to produce coherent output, because nothing is deciding what runs when, in what order, or what happens when a step fails.

<Section index="04" kicker="Layer 4" title="Governance: the immune system">

Governance is the layer easiest to misdraw as a gate at the end — a review step before launch. The course's framing is the opposite: it's an envelope running continuously across every other layer, checking consent, claims, and bias while decisions are being made, not after.

<DefinitionList items={[
  { term: 'Consent gates', body: "No consent, no run. If it can't be confirmed, the system stops rather than proceeding on an assumption." },
  { term: 'Claims verification', body: 'If the AI says it, it has to be on the approved list — no exceptions for phrasing that sounds close enough.' },
  { term: 'Bias detection', body: 'Watches who a model favors and who it leaves out, with accuracy thresholds checked per group, not just in aggregate.' },
  { term: 'Kill-switch protocols', body: 'A defined halt mechanism with real thresholds — e.g. a consent-check outage past 60 seconds halts everything, not just the affected service.' },

Marko, the multi-agent system they built on top of that stack, proved itself on one narrow use case before scaling, with governance agents at every step rather than one review at the end. A strategic decision — which segment to prioritize, which claim is safe to make — isn't separate from this stack. It's the thing the stack exists to carry, correctly, from the moment a signal arrives to the moment a customer sees the result.
