Marketing has always done three recurring jobs: understand the customer's world, build the system that serves them, and run that system while it keeps improving. What changes with I-MOS isn't the jobs — it's that each one now maps to a specific, connected piece of work instead of a department's worth of disconnected activity.

<Section index="01" kicker="The loop" title="Understand, Build, Run">

Seven workflows, three phases, one loop. **Understand** is Sense and Focus — reading signal, then turning it into a target. **Build** is Design and Attract — encoding the brand into content, then winning discovery for it. **Run** is Orchestrate, Execute, and Learn — deciding the next action, delivering it, and measuring what it caused.

The order is load-bearing, not decorative. Understanding has to precede Building — you can't encode Brand DNA into content blocks for a customer you haven't defined. Building has to precede Running — there's nothing for Orchestrate to sequence until Design and Attract exist. Skip a phase and the next one runs on guesses instead of inputs.

<Section index="02" kicker="Role, not just name" title="What each workflow actually does">

"Sense the market" and "sense continuously, on every signal, with the result available to the next workflow before a human opens a dashboard" are different claims. The second is what the loop requires.

<DefinitionList items={[
  { term: 'Sense', body: 'Always-on listening across behavioral, intent, and qualitative signal — not episodic research. Breaks down the moment insights live in a slide deck instead of a system Focus can read.' },
  { term: 'Focus', body: 'Turns signal into a living ICP, a positioning stance, and a messaging hierarchy — written so a system, not just a person, can act on it.' },
  { term: 'Design', body: 'Encodes Brand DNA as modular, machine-readable rules so content can be assembled at scale without re-litigating brand fit on every asset.' },
  { term: 'Attract', body: 'Engineers discovery — owned content, third-party presence, and answer-engine visibility built to be found, not just published.' },
  { term: 'Orchestrate', body: "Converts customer state into operating logic: entry and exit criteria, next-best-action rules, escalation conditions. The decision architecture." },
  { term: 'Execute', body: 'Delivers continuously — budget, creative, and channel mix adjusted against live signal, not last quarter\'s plan.' },
  { term: 'Learn', body: "Moves past what happened to what marketing actually caused, and structures that finding so it feeds the next cycle automatically." },
]} />

Each entry names a *breakdown mode* on purpose. A workflow that produces the right artifact but hands it off as a PDF or a meeting note hasn't actually joined the loop — it's produced good work that still requires a person to carry it to the next step by hand, which is the exact failure this handbook opened on.

</Section>

<Section index="03" kicker="The compounding step" title="The Learn→Sense feedback arc">

Six of the seven workflows form a line. Learn is the one that bends back. When Learn isolates what a campaign actually caused — not just what correlated with it — that finding doesn't stop at a dashboard. It writes into Shared Memory as a new prior: an updated signal threshold, a refined ICP weight, a next-best-action rule Orchestrate didn't have last cycle. Sense then starts its next pass already smarter than the last one.

This is the single mechanical difference between a system that compounds and one that resets. Without the return arc, every quarter starts from the same blank assumptions the last one did, no matter how much was measured in between.

<Example id="airbnb-lighthouse">
  Project Lighthouse runs continuous bias monitoring across Airbnb's booking and pricing algorithms — checking during decisions, not auditing after them. That's Govern's job description in miniature: not a gate a launch passes through once, but a check that runs the same way, every time, on every workflow, for as long as the system operates.
</Example>

</Section>

<Section index="04" kicker="Loop, not list" title="Why the sequence, not the checklist, is the point">

It would be possible to run all seven workflows well and still not have I-MOS — if each one's output required a person to reformat, re-key, or re-explain it before the next workflow could use it. The test the course applies to every handoff is simple: can the downstream workflow consume this output without a human translating it first? A positioning statement written as prose fails that test. The same positioning encoded as a weighted ICP model a system can score against passes it.
